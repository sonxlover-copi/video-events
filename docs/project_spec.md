# Спецификация MVP: Traffic Line Counter

## Клиентская задача

На записи с одной неподвижной камеры посчитать транспорт, прошедший через заданную контрольную линию, сохранить момент каждого пересечения и дать оператору видео для ручной проверки.

Формулировка ограничена одним видеофайлом, одной сценой, одной линией и классами COCO `car`, `motorcycle`, `bus`, `truck`. Это демонстрационный локальный пилот и база для узкой услуги «аудит/доработка видеоинференса и экспорт событий».

## Входы и выходы

**Входы**

- видеофайл, который декодирует OpenCV;
- YAML-конфигурация: локальная модель, устройство вычислений, классы, порог confidence, размер модели, трекер, два нормализованных конца линии и deadband в пикселях.

**Выходы**

- `annotated.mp4`: H.264-видео с боксами/track ID от YOLO, контрольной линией, накопленными количествами и маркером нового события;
- `events.csv`: одна запись на переход track ID через конечный отрезок, с кадром подтверждения и оценкой момента пересечения;
- `summary.json`: параметры обработки, число кадров, число событий по классу и направлению, время обработки и FPS полного прохода.

**Команды**

- `video-events inspect --input FILE` — метаданные и проверка декодирования первого кадра;
- `video-events count --input FILE --config YAML --output-dir DIR` — полный офлайн-проход.

## Логика подсчёта

YOLO11n обнаруживает объекты; встроенный ByteTrack связывает детекции внутри одного видео. Центр bounding box задаёт точку траектории. Линия ориентирована `start → end`; знак её нормированного знакового расстояния задаёт стороны `negative` и `positive`. Смена стороны учитывается после выхода центра за deadband на противоположной стороне. Пересечение бесконечной прямой засчитывается только тогда, когда точка пересечения лежит на заданном конечном отрезке. Время события линейно интерполируется между двумя последними стабильными положениями track ID; в CSV отдельно записывается кадр, на котором переход подтвердился.

Это устраняет часть ложных переключений из-за небольшой дрожи bbox, но не исправляет ошибочную детекцию или ID switch трекера. При окклюзии объект может получить новый ID и породить пропуск или повторный счёт. Ручное сопоставление направлений с терминами «въезд/выезд» зависит от размещения камеры и линии.

## Вне объёма MVP

- RTSP, live-поток, повторное подключение камер;
- веб-интерфейс, FastAPI, Docker и база данных;
- обучение/дообучение собственного детектора;
- калибровка камеры, скорость в физических единицах;
- распознавание номеров, лиц, намерений или поведения;
- подсчёт людей, очередей, парковочных мест и объектов за пределами выбранных классов;
- гарантия точности для новой сцены без проверки на данных клиента.

Эти функции рассматриваются только после появления конкретного требования и отдельной оценки.

## Текущая приёмка вертикального среза

- команда `inspect` выдаёт читаемые свойства видео и завершается ошибкой на невалидном/пустом источнике;
- `count` сохраняет все три артефакта, включая пустой CSV со схемой при нуле событий;
- конфиг отвергает неизвестные классы, неверные координаты и некорректные параметры;
- события относятся к пересечениям конечного отрезка, содержат track ID, класс, направление и время;
- README позволяет запустить обе команды без редактирования кода.

Это техническая приёмка, она не подтверждает точность детектора или счётчика.

## Условия коммерческой готовности

До обещания клиенту метрик необходимо получить разрешённые клипы с целевой сцены и создать ground truth пересечений независимо от запуска модели. Train/tuning и финальные клипы разделять по исходному видео/сессии, а не по соседним кадрам. На финальном наборе показать количество TP/FP/FN, event precision/recall, дубликаты, погрешность времени, count MAE по клипам и скорость на описанном железе.

Целевые пороги плана (precision не ниже 0,90 и recall не ниже 0,85) являются gate для конкретного пилота, не свойством текущей версии и не обещанием для неизвестных записей. Если выборка мала или порог не достигнут, публиковать числа и ограничения без заявления о готовности.

## Лицензии и данные

Локальные веса `models/yolo11n.pt` не включены в Git. Перед закрытым коммерческим развёртыванием проверить применимые условия Ultralytics, модели и обучающих данных; экспорт в другой формат сам по себе не отменяет условия исходного компонента. Клиентские видео и результаты разметки не публиковать без письменного разрешения.
