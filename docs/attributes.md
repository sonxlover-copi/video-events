# Цвет кузова и распознавание номеров

## Подготовка и запуск

Из корня проекта:

```bash
uv sync --locked --extra plates
uv run --extra plates video-events prepare-plates
uv run --extra plates video-events count \
  --input data/processed/ua_detrac/MVI_40204.mp4 \
  --config configs/ua_detrac_mvi40204_line_y054_lowconf.yaml \
  --output-dir runs/my-attributes-check --colors --plates
```

Интернет нужен при установке и подготовке весов. `prepare-plates` загружает детектор `yolo-v9-t-384-license-plate-end2end` и OCR `cct-xs-v2-global-model` в стандартные кеши библиотек, затем открывает обе ONNX-сессии. При обработке отсутствующие файлы вызывают ошибку до создания результатов. Повреждённые файлы можно заново скачать через `prepare-plates --force`.

Детектор транспорта использует устройство из YAML. Детектор номера и OCR работают на CPU с двумя вычислительными потоками. Отдельные сервисы и внешние API не используются. Базовый счётчик без флагов сохраняет прежние CSV и `schema_version: 1`; с признаками сводка имеет `schema_version: 2`.

Устанавливай зависимости через `uv`: в `pyproject.toml` исключён второй дистрибутив OpenCV, который транзитивно запрашивает FastALPR. Проект предоставляет `cv2` через уже используемый `opencv-python`. Совместная установка двух сборок, владеющих одними файлами `cv2`, мешает безопасно переключать extras. Механизм исключения описан в [документации uv](https://docs.astral.sh/uv/concepts/resolution/#dependency-exclusions).

## Настройки

| Флаг `count` | По умолчанию | Назначение |
| --- | --- | --- |
| `--colors` | выключен | Оценивать цвет кузова |
| `--plates` | выключен | Читать номера и подтверждать повторные чтения |
| `--attribute-interval` | `10` | Минимальное расстояние между анализируемыми кадрами одного трека |
| `--plate-min-confidence` | `0.85` | Минимальный средний confidence символов OCR |
| `--plate-min-observations` | `2` | Число одинаковых чтений для подтверждения, не меньше двух |
| `--plate-format` | `generic` | `generic` для 4–12 латинских букв/цифр; `ru` для стандартной формы автомобильного номера РФ |

Интервал задаётся в кадрах: 10 кадров при 25 FPS — около 0,4 с. Для коротких треков его можно уменьшить. Частые наблюдения увеличивают вычислительную нагрузку и сами по себе не доказывают правильность OCR.

## Как определяется цвет

Из исходного кадра вырезается рамка машины. Анализируется внутренняя область по ширине 15–85% и по высоте 35–80%: это снижает влияние фона, окон и колёс. Пиксели классифицируются по оттенку, насыщенности и яркости HSV. Поддерживаются `black`, `white`, `gray`, `red`, `orange`, `yellow`, `green`, `blue`, `purple`, `brown` и `unknown`.

Для рамок меньше 40×30 px цвет не определяется. Цвет одного наблюдения принимается при доле доминирующих пикселей от 45%. Для итогового признака нужны два одинаковых наблюдения и поддержка минимум 60% среди всех цветовых проб трека, включая неопределённые. Белый и серебристый кузов в тени могут выглядеть серыми; `gray` не различает серую краску и металлик.

Это эвристическая оценка видимого цвета без сегментации кузова и без обученного классификатора. Блики, ночь, цветное освещение, реклама, перекрытия и фон внутри рамки могут менять результат. Число `color_support` показывает согласованность наблюдений, а не вероятность истинного цвета.

## Как подтверждается номер

На достаточно крупном изображении машины ищется отдельная рамка номера. В OCR передаются только рамки номера размером от 48×12 px; весь crop машины должен быть не меньше 80×40 px. Модель читает исходные пиксели до наложения подписей. Выход нормализуется: убираются пробелы, дефисы и конечное заполнение `_`, визуально совпадающие кириллические буквы переводятся в латиницу. Сомнительные замены букв на цифры не выполняются.

При нескольких пригодных номерах в рамке машины наблюдение пропускается. При одном кандидате учитываются текст и confidence. Одинаковый текст подтверждается после заданного числа наблюдений при доле не ниже 60% от всех принятых чтений этого ID. Конфликтующие чтения могут снять подтверждение. Пропуск детекции номера не считается голосом против ранее прочитанного текста.

Повторяющаяся ошибка OCR тоже может получить подтверждение. `confirmed` означает согласованность распознавания, а не сверку с реестром. Чужой номер внутри перекрывающейся рамки, смена ID и нечитаемые символы остаются ограничениями. Режим `ru` проверяет структуру обычного автомобильного номера; специальные, двухстрочные и другие форматы отдельно не поддерживаются. На российских номерах количественная точность пока не измерялась.

Использованы [FastALPR](https://github.com/ankandrew/fast-alpr), [Open Image Models](https://github.com/ankandrew/open-image-models) и [Fast Plate OCR](https://github.com/ankandrew/fast-plate-ocr). Сводка запуска сохраняет имена и SHA-256 файлов моделей. Условия этих компонентов и моделей рассматриваются отдельно от исходного кода Video Events.

## Выходные поля

| Поле | Смысл |
| --- | --- |
| `vehicle_color` | Подтверждённый цвет или `unknown` |
| `color_support` | Доля голосов за ведущий цвет, даже если подтверждения ещё нет |
| `color_samples` | Число проб цвета |
| `plate_text` | Подтверждённый текст; пустая строка, если подтверждения нет |
| `plate_confidence` | Среднее confidence принятых чтений подтверждённого текста; иначе 0 |
| `plate_support` | Доля ведущего текста среди принятых чтений |
| `plate_observations` | Число совпавших чтений ведущего кандидата |
| `plate_status` | `disabled`, `not_read`, `unconfirmed`, `ambiguous` или `confirmed` |

`events.csv` содержит снимок признаков на кадре подтверждения пересечения. `vehicles.csv` содержит итог по всему клипу, время первого/последнего появления и число попыток OCR. Поэтому номер может быть пустым в раннем событии, но появиться в итоговом каталоге. Строка каталога соответствует ID трекера: смена ID может создать несколько строк для одной машины. `tracked_ids`, `by_color` и `confirmed_plates` в сводке также считаются по ID.

## Воспроизводимая демонстрация

После подготовки весов:

```bash
uv run --extra plates python scripts/run_attributes_demo.py --download-example
```

Скрипт загружает контрольную фотографию из репозитория FastALPR, если её ещё нет локально, создаёт восьмисекундное панорамирование и запускает настоящий `count_video`. Результат — в `runs/attributes/photo-pan/result/`. Для повторного запуска укажи новую папку через `--output-dir`.

Это проверка связки YOLO → ByteTrack → цвет/OCR → событие → CSV. Панорамирование фотографии не заменяет проверку на реальном движении и не используется для метрик точности.
