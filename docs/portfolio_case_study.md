# Video Events — счётчик транспорта по контрольной линии

## Короткое описание

Собрал офлайн-прототип, который считает транспорт, пересекающий заданную линию на записи с одной неподвижной камеры. YOLO11 обнаруживает автомобили, мотоциклы, автобусы и грузовики, ByteTrack связывает объекты между кадрами, а отдельный геометрический модуль регистрирует пересечение линии. Для каждого запуска программа сохраняет видео с визуальной разметкой, CSV событий и JSON-сводку.

**Стек:** Python 3.12, PyTorch, Ultralytics YOLO11, ByteTrack, OpenCV, FFmpeg, YAML, CLI.

**Ссылки в репозитории:** [исходный код](../src/video_events/), [конфиги](../configs/), [отчёт с метриками](../reports/ua_detrac_mvi40201_baseline.md), [README с запуском](../README.md).

## Задача

При просмотре записи с дорожной камеры оператору нужно узнать, сколько машин прошло через выбранный участок дороги, в каком направлении они двигались и когда произошло каждое пересечение. Ручной просмотр требует времени, а одного детектора недостаточно: детекция на отдельном кадре не показывает, пересёк ли объект линию и не был ли он посчитан повторно.

Цель прототипа — превратить запись с одной стационарной камеры в проверяемый список событий и размеченное видео, в котором оператор может быстро просмотреть результат.

## Решение

Пользователь передаёт видео и YAML-конфигурацию с классами транспорта и координатами контрольной линии. Пайплайн обрабатывает запись локально, без сервера:

1. OpenCV читает видео и проверяет, что кадры декодируются.
2. YOLO11n находит объекты выбранных классов.
3. ByteTrack связывает детекции в треки внутри видео.
4. Счётчик отслеживает положение центра рамки относительно ориентированного конечного отрезка. Deadband снижает влияние небольшого дрожания рамок, а событие засчитывается только при пересечении самого отрезка.
5. CLI сохраняет `annotated.mp4`, `events.csv` и `summary.json`.

В CSV записываются класс, ID трека, направление, кадр подтверждения, оценка времени пересечения и точка пересечения в пикселях. Время интерполируется между соседними устойчивыми положениями трека.

## Результаты разработки

Сравнил события с траекториями XML-разметки двух последовательностей train-части UA-DETRAC. Для совпадения событий использовались одинаковые класс и направление, допуск ±1 секунду и расстояние между точками пересечения до 40 пикселей. Класс `van` из разметки объединялся с `car`, потому что у используемой COCO-модели нет отдельного класса фургонов.

| Последовательность | Эталон событий | Precision | Recall |
| --- | ---: | ---: | ---: |
| MVI_40201 | 103 | 0.978 | 0.845 |
| MVI_40204 | 134 | 0.991 | 0.866 |

При сравнении порогов низкий порог детектора вместе со вторым порогом ByteTrack `0.05` увеличил recall на этих клипах без роста числа FP: с 0.806 до 0.845 на MVI_40201 и с 0.828 до 0.866 на MVI_40204. Порог создания нового трека оставлен `0.25`, чтобы слабые детекции могли поддерживать существующую траекторию, но сами не начинали новую.

Дополнительно на MVI_40204 одно автобусное пересечение на выбранной линии совпало с XML. На MVI_40141 модель визуально обнаружила мотоцикл и зарегистрировала его пересечение; отдельной разметки мотоциклов для этого клипа нет, поэтому это ручная проверка, а не метрика качества.

## Ограничения

- Проверка выполнена на двух последовательностях train-части с похожей геометрией дороги; это dev-результаты, а не независимый тест на другой камере.
- Параметры линии настраивались под тестовые сцены. Для новой камеры координаты нужно подобрать заново.
- Окклюзии и смена ID трекера могут приводить к пропуску или повторному подсчёту.
- Для мотоциклов нет количественной оценки, а автобусный результат основан на одном эталонном пересечении.
- MVP обрабатывает только записанное видео: нет RTSP/live-потока, межкамерного трекинга, измерения скорости и распознавания номеров.

Поэтому проект показывает рабочий CV-пайплайн и способ оценивать события, но пока не даёт основания обещать точность на произвольной камере. Следующий этап для пилота — разметить независимые клипы с целевой камеры и заранее зафиксировать метрики и пороги сопоставления.

## Что можно адаптировать под заказчика

В текущем объёме прототип можно использовать как основу для узкой задачи: обработать архивную запись с одной камеры, настроить контрольную линию, выдать список пересечений и видео для ручной проверки. Перед такой работой нужно проверить формат и качество исходного видео, согласовать классы и направление подсчёта, а точность оценить на размеченных клипах заказчика.
