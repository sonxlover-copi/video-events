# Подготовка данных и обучение классификатора

В проект добавлен воспроизводимый эксперимент на UA-DETRAC Train. Он показывает
работу с разметкой, PyTorch, torchvision, аугментациями и оценкой модели на сценах,
которые не участвовали в обучении.

## Подготовка выборки

В корне проекта:

```bash
uv run python scripts/train_vehicle_classifier.py prepare
```

Скрипт читает XML и кадры прямо из локальных архивов `data/raw/ua_detrac/`.
Источник датасета и требуемые имена архивов перечислены в [памятке по данным](data.md).
Сценой считается исходная видеопоследовательность: 20% сцен резервируются для
проверки, а все кадры каждой сцены остаются в одной части. Фиксированный seed
делает разбиение воспроизводимым. Для снижения близости соседних кадров берётся
каждый десятый кадр; кропы приводятся к 64×64, а в обучающей части ограничено
число примеров на класс.

Перед сборкой кропов скрипт проверяет координаты, размеры рамок и классы. Боксы,
частично выходящие за границы кадра, считаются кандидатами на ручную проверку:
для обрезанного краем изображения транспорта это может быть ожидаемой разметкой,
а не ошибкой. При подготовке такие боксы обрезаются по границе кадра. Категория
`others` не включена: в выбранной разметке она намного реже трёх целевых классов.

Локально создаются `data/processed/vehicle-classifier/dataset.npz` и
`data_report.json`. Архив данных и исходные изображения в Git не добавляются.

## Обучение и оценка

```bash
uv run python scripts/train_vehicle_classifier.py train --epochs 12
uv run python scripts/analyze_vehicle_classifier.py
```

Обучается собственная компактная depthwise-separable CNN без предобученных весов.
AdamW и аугментации torchvision применяются к кропам. При выборе пакетов вес
каждого трека внутри класса одинаков, чтобы длинная размеченная траектория не
получала больший вес из-за числа кадров. Лучшая эпоха выбирается по macro F1 на
отложенных треках после усреднения вероятностей всех наблюдений одной машины.
Анализатор сравнивает модель с majority baseline и сохраняет локальную галерею
ошибок с исходными именами последовательностей, ID траекторий и размером рамки.

Модель и полный отчёт сохраняются в локальный каталог данных. В репозитории
публикуется только агрегированный отчёт в
[`reports/vehicle_classifier_2026-11-10.json`](../reports/vehicle_classifier_2026-11-10.json).

Результаты разбора baseline, повторных кадров и размеров объектов публикуются в
[`reports/vehicle_classifier_error_analysis_2026-11-10.json`](../reports/vehicle_classifier_error_analysis_2026-11-10.json).

На RTX 5060 Laptop модель получила **macro F1 0,781** по 882 уникальным трекам
из 12 отложенных последовательностей. По классам: `car` — F1 0,955 (770 треков),
`bus` — 0,744 (19), `van` — 0,644 (93). Majority baseline, который всегда
предсказывает наиболее частый среди train-треков класс `car`, даёт macro F1
**0,311**. Его accuracy по трекам при этом 0,873 из-за перекоса в отложенных
сценах, поэтому ориентироваться только на accuracy нельзя.

В массиве было 4 331 кроп, но 711 из 882 отложенных треков представлены несколькими
кадрами (в среднем 4,91 кропа на трек). Эти кадры похожи и не являются независимыми
примерами. Поэтому скрипт усредняет вероятности на уровне трека и использует
track-level macro F1 для выбора эпохи. В train-части было 87 размеченных автобусных
треков, а в validation — всего 19: оценка `bus` пока нестабильна.

Главная ошибка среди фургонов — `van` → `car`: 33 из 93 validation-треков. Она
сохраняется и на крупных боксах, поэтому проблему нельзя объяснить только
разрешением маленьких кропов. Локальная галерея помогает проверять отдельные
рамки и спорную границу между классами; изображения датасета в Git не публикуются.

Эта задача классифицирует уже обрезанные по эталонным боксам объекты. Она не
обучает и не заменяет YOLO-детектор. Проверка выполнена на части UA-DETRAC Train,
а не на независимом наборе с другой камерой; метрики нельзя трактовать как качество
боевого определения типа транспорта. Классы `car`, `bus` и `van` также зависят от
таксономии этого датасета и не совпадают один к одному с классами COCO в основном
счётчике.
